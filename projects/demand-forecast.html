PROJECT 01 · SUPPLY CHAIN DATA AUTOMATION

Demand & Planning Monitoring.

Turning fragmented planning data into a structured, automated monitoring workflow for demand forecasts, component requirements and production scheduling.

CONTEXT Supply Chain Planning Internship
COMPANY TE Connectivity · TAC1
TOOLS Excel · Power Query · VBA · Power BI · DAX
01 / OVERVIEW

From weekly files to planning visibility.

During my Supply Chain internship at TE Connectivity, I worked on the monitoring of customer demand forecasts and their impact on component requirements and production scheduling.

The objective was to move from a highly manual weekly process toward a more structured workflow capable of preparing, transforming, refreshing and analysing planning data with fewer repetitive interventions.

The solution combined Power Query, Excel VBA and Power BI, with dynamic DAX measures used to keep the analysis reusable when new weekly EDI data was loaded.

02 / THE CHALLENGE

Too much manual work. Not enough visibility.

Each week, planning information from different sources had to be prepared and consolidated before it could be analysed. This created repetitive operations and made weekly monitoring more time-consuming.

01 Multiple planning files and data sources
02 Repetitive cleaning and consolidation
03 Forecast changes difficult to monitor
04 Limited visibility on component and production impacts
03 / THE SOLUTION

A connected workflow for weekly monitoring.

Instead of treating each week's files as a separate manual exercise, I structured the process as a connected workflow.

Power Query handled data preparation and transformation, Excel VBA automated repetitive workbook operations, and Power BI provided the monitoring layer.

Turning raw planning files into analysis-ready data.

Before the data could be analysed in Power BI, the incoming planning files had to be prepared and standardised. Power Query was used to automate this preparation and create a consistent structure for the weekly data.

One important step was the transformation of the calendar-week columns into rows through an Unpivot operation. This made the weekly forecast information easier to analyse over time in Power BI.

07 / DYNAMIC ANALYTICS

Making the indicators dynamic and reusable.

DAX measures were developed to make the Power BI analysis responsive to the selected product, customer and EDI context.

The objective was to avoid creating a new calculation every time new weekly EDI data was loaded. Instead, the measures determine the relevant EDI sequence dynamically and recalculate the indicators according to the new data.

01

EDI Variation

Compare the current EDI forecast with the previous EDI while preserving the selected product and customer context.

02

Weekly Reusability

Recalculate the same measure automatically when new weekly EDI data is added to the model.

03

Dynamic Context

Keep the indicators responsive to the selected customer, part number and EDI context.

DAX · EDI VARIATION

Comparing successive EDI forecasts dynamically.

The first measure was designed to identify changes in customer demand by comparing the current EDI forecast with the previous EDI.

The calculation uses the current EDI context and dynamically retrieves the previous EDI, allowing the same logic to continue working when new weekly EDI data is added to the model.

DAX — dynamic comparison between the current EDI forecast and the previous EDI.

DAX · COMPONENT REQUIREMENTS

Translating forecast demand into component requirements.

A second measure was developed to translate the forecast quantity of finished products into component requirements using the Bill of Materials.

The calculation iterates through the BOM structure and combines the required quantity per parent with the corresponding forecast quantity to determine the total component requirement.

DAX — dynamically translating forecast quantities into component requirements through the BOM.
